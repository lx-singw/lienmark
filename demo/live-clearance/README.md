# The Last Rehearsal — live clearance demonstration

These are editable, fictional production inputs. They contain no approved decisions, search results or predetermined model outputs. The initial three occurrences become four in the proposed revision: the piano use changes duration and a commercial recording is added. Counts in the application are computed from the resulting records.

1. Use a dedicated production named **The Last Rehearsal — demonstration**. Authorize an allowance and connect the watched folder in Workspace settings.
2. Upload `baseline.json` or place it in the production's `locked` folder. JSON supplies explicit occurrence facts; it does not exercise text extraction. The separate live Fountain verification exercises extraction. Follow the actual research and inspect the sources.
3. Open a privately issued reviewer invitation in a separate browser profile. The human operator must inspect and record each baseline decision, with a rationale explicitly identifying the fictional rehearsal. Do not present those actions as a lawyer's real approval. If a finding is incomplete, provide supporting information or leave it unresolved.
4. Close the workspace. Place `revision.json` in the watched folder. Reopen to see detection, preserved decisions and the affected research. You may edit the duration, asset or scope before submission; the system must compute the consequences.
5. Supply `performance-scope.txt` through the piano clarification. It confirms scenario facts but does **not** grant rights. The model may retain missing permissions. An arriving real authorized agreement would need to address the actual open questions.
6. Have the assigned human reviewer record the supported decision or exception. Keep the new commercial recording unresolved unless evidence and review support a different result. Export the draft PDF and execution record from Delivery.
7. Re-upload an identical document under another filename: no new provider work should be created. Controlled process-death recovery is verified separately by `tests/test_clearance_adk.py`.

For automated integration verification, `python -m scripts.verify_clearance_outcome --allowance 2` uses these files, real provider calls, and **explicitly simulated reviewer actions** in an isolated temporary production. The result is test evidence, not a recorded human review or legal clearance. It does not populate the live workspace.

A three-minute recording can allocate 20 seconds to the production problem and reviewed baseline, 35 to automatic detection and selective carry-forward, 50 to research and evidence, 35 to clarification/resumption, and 40 to the human decision and delivery outcome. Record the functioning build; disclose any elapsed-time cuts and simulation. Avoid displaying access tokens.
